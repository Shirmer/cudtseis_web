# 团队工具接入建议

目前官网、地震目录、Terra 为静态页面或演示工具。本文为后续接入约定，不代表已经部署成员工具，也不改变现有学校网关、frp 或 App 配置。

## 入口与部署边界

建议在拿到首个工具后创建 `/station/` 地震台门户；首页“成都理工大学地震台”板块和导航进入该门户。门户按用途列出工具，标明简介、维护人、使用范围、版本和使用文档。Terra 保留分析工具导航；同一工具可从两个入口打开，不复制服务。

官网只管理入口和介绍；工具独立版本、独立目录、独立进程或容器。大型计算继续在学校服务器运行，腾讯云仅在需要时提供 HTTPS 和受限转发。已有 App 后端不与工具混用部署目录或数据库账号。

| 工具类型 | 交付方式 | 建议入口 |
| --- | --- | --- |
| 纯浏览器计算或静态展示 | 源码、构建说明、构建后的静态产物 | 可信且完成审查的小工具可用 `/tools/工具名/`，需支持该部署前缀 |
| Streamlit、Dash、Shiny、Python API 等服务 | Dockerfile、Compose 示例、依赖锁定文件、启动及健康检查说明 | 优先独立工具子域名，经学校批准的反代接入 |
| 长时间计算、GPU 或大量上传 | Web/API 服务加任务队列和受限工作进程 | 返回任务编号，异步查询结果；登录并配置配额 |
| 暂无网页界面的脚本或桌面软件 | 可运行示例、输入输出规范及授权信息 | 先提供使用说明或下载，另行设计网页/API，不直接公开开发进程 |

工具子域名需要学校批准 DNS、证书与反代配置；不能假定学校已开放。现有 `seis.cdut.edu.cn` 不受这项规划影响。若只能使用域名下的路径，需逐工具确认静态资源、API、登录 Cookie 和 WebSocket 均支持前缀，不能仅靠首页跳转验证。

独立工具子域名可隔离浏览器存储和同源权限；服务端仍须使用独立账号、容器和访问控制。初期采用正常链接打开工具，不默认 iframe 嵌入，以减少登录、浏览器权限和全屏操作问题。工具页面提供“返回研究中心”。

## 成员交付清单

1. 工具名称、用途、维护人及代码仓库；确认是否允许公开访问。
2. 技术栈、依赖锁定、启动/构建命令、支持的部署前缀及健康检查。
3. 一份可公开的示例输入、预期输出与操作说明。
4. CPU、内存、磁盘、GPU 需求；单次运行时间和预计并发。
5. 登录、上传、外部 API、数据库、WebSocket、许可证及敏感数据需求。
6. 配置示例使用 `.env.example`，不提交密钥、真实用户数据或生产数据库。

## 学校服务器运行约定

- 每个服务独立目录，例如 `/srv/research-tools/waveform-viewer/`，包含自己的部署文件、数据与回滚说明。目录隔离需配合权限与容器隔离，单靠文件夹不提供安全边界。
- 动态服务只绑定 `127.0.0.1` 或隔离的容器网络；通过受控反代公开，数据库、调试器和管理端口不直接开放。
- 禁用开发调试模式；以非 root 用户运行，限制 CPU、内存、进程数和磁盘使用，并设置日志轮转。容器不挂载 Docker socket，不使用特权模式。
- 上传限制类型、大小和保存位置；计算结果设过期清理。长任务设超时、队列长度和用户配额，避免占满学校服务器。
- 涉及计算消耗或非公开数据的工具，明确登录和授权；限流不能代替身份认证。公开只读工具可单独评估匿名访问。
- HTTPS、认证和来源控制须在实际服务/API 端执行，不能只在官网隐藏按钮。
- 新增 frp 映射时仅转发必要的本机服务，保持双向 TLS、来源限制和回环监听；不开放任意端口范围，不转发数据库。

## 发布流程

成员在自己的仓库维护工具 → 提供固定版本 → 校内测试入口验证 → 复核资源与访问权限 → 部署正式版本并保留上一版本 → 官网增加真实入口。

首个工具接入时先完成一个闭环，再复用其交付约定。不先搭建复杂的插件平台或统一重写成员工具。工具是否上线与官网内容发布分开进行。
