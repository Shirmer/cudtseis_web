> 本文为历史科研平台代码盘点，不代表当前静态网站已接入或上线这些能力。当前页面范围以 [README](../README.md) 为准。
>
> 盘点时间：2026-10-26。依据：`main` 分支前端（Dashboard / History / Papers / Knowledge / RAG / Terra）、
> `Project-Code/backend`（FastAPI + PostGIS + RAG）、`dev1` 分支的三维地球。
> 只列**代码里真实存在**的功能，不含设想。

---

## 0. 一句话理解这个平台

平台围绕**一个地震事件**组织全部能力：

```
实时目录 / 历史检索  →  事件详情  →  关联论文  →  RAG 证据  →  结论
        ↑                                      ↓
   三维地球（空间视角）                    论文库 / 知识库（长期积累）
```

## 2. 逐模块

### A. 实时地震目录

**用户任务**：打开就知道当前地震活动；点一个事件看详情与相关文献。

**页面结构**（三栏 + 顶栏）：

- 顶栏：`CDUT SEIS` / 成都理工大学地震研究中心 / 实时监控运行中 / 中文翻译 / 历史数据 / 文献问答
- 左栏「实时地震列表」：
  - 24h 事件数、最大震级、浅源事件数
  - 事件列表（点击联动地图与文献检索）
- 中央地图：
  - 震级色标 3–4 / 4–5 / 5–6 / 6+
  - 震级制式、定位源切换
  - 缩放、底图
- 右栏「地震详情与科研解读」：
  - 监测概览、平均深度
  - 事件详情：更新时间、震级类型、Gap、RMS、水平/深度/震级误差、定位来源、震级来源、NST/MagNST
  - 一句话判断（Research Conclusion）
  - 关联论文、主题信号
  - 面板可收起

**状态**：实时推送中 / 无事件 / 文献检索暂不可用 / 加载中。

**接口**：`GET /api/events`、`GET /api/stream`（SSE）、`GET /api/events/{id}/research`。

**设计注意**：信息密度高，地图是主视觉；「实时」要有明确的状态表达；右栏是二级信息，适合抽屉/侧滑。

---

### B. 历史数据检索

**用户任务**：按时间、空间、震级、深度组合查询，看分布与统计。

**页面结构**：

- 查询工作台（表单 + 地图 + 结果）
- 时间：近 24h / 72h / 7 天预设、开始/结束时间、时间窗口（小时）
- 震级：最小/最大
- 深度：最小/最大（km）
- 空间：最小/最大经纬度、「使用当前视野」
- 结果上限、重置、清空时间、清空空间
- 结果列表 + 地图联动 + 历史地震速览
- 底图：浅色 / 地形

**状态**：空结果 / 超限 / 加载中 / 参数错误。

**接口**：`GET /api/events/search`（分页）。

**设计注意**：表单与地图要能同时看见；结果表格要能扫读；移动端折叠成「条件 → 地图 → 列表」。

---

### C. 事件科研解读

**用户任务**：针对选中的事件，得到可引用的科学解读。

**输出结构**（后端真实字段）：

- `summary`：一句话判断
- `cohort`：同类事件/统计背景
- `topicSignals`：主题信号
- `papers`：关联论文
- `queryPlan`：检索计划
- `sourceBreakdown`：来源分布
- `notes`：补充说明
- `mode` / `generatedAt`
- `workflow`：步骤（观测 → 目录 → 事件 → 文献 → 证据 → 结论）

**页面/组件**：事件头部（震级/位置/深度/时间）、一句结论、证据链、论文卡、主题标签、工作流时间线。

**状态**：无关联文献 / 检索失败 / 生成中 / 部分结果。

**接口**：`GET /api/events/{id}/research`、`GET /api/events/{id}/workflow`、`POST /api/events/{id}/rag`、`POST /api/events/{id}/vector-index`。

**设计注意**：这是平台最有差异化的模块，适合做成「事件 → 论文 → 结论」的可视化证据链，而不是普通详情页。

---

### D. 论文数据库与检索

**用户任务**：搜论文、看证据片段、进论文详情。

**检索页**：检索问题、检索后端、结果数量、限定论文 ID、常用问题、去工作台问答；结果含标题/作者/期刊/年份/证据片段。

**论文详情**（五段式）：

1. 核心结论（Core Conclusion）
2. 适用范围（Regional Applicability）
3. 引用建议（Citation Guidance）
4. 方法边界（Method Limits）
5. 地震专业解读（Seismic Reading）

**元数据**：DOI、期刊、主题、证据类型、论文关系、分块（chunks）。

**接口**：`GET /api/papers`、`GET /api/papers/{id}`、`POST /api/papers`、`GET /api/papers/architecture`、`GET /api/papers/storage`。

**状态**：无结果 / 加载中 / 论文不存在。

**设计注意**：学术阅读版式；五段式适合做锚点导航；引用要显眼、可复制。

---

### E. 文献入库与知识库

**用户任务**：把 PDF 论文导入系统，建立可检索的知识库。

**导入方式**：单篇导入 / 批量导入；上传到服务器 / 服务器已有文件。

**元数据表单**：标题、作者、年份、DOI、来源链接、文献文件。

**过程与结果**：元数据卡片、RAG 引擎状态、原文存储、导入结果、批量任务进度。

**接口**：`POST /api/documents/upload`、`POST /api/documents/ingest`、`POST /api/documents/batch-ingest`、`GET /api/documents/import-jobs`、`GET /api/documents/{id}/status`、`GET /api/documents/{id}/file`；`POST /api/knowledge/init`、`/search`、`GET /api/knowledge/units/{id}/context`。

**状态**：上传中 / 解析中 / 失败 / 部分成功。

**设计注意**：向导式（选方式 → 填元数据 → 上传 → 解析进度 → 结果）；错误要能定位到具体文件。

---

### F. RAG 问答 / Terra 工作台

**用户任务**：用自然语言问文献问题，答案带引用。

**RAG 知识库**：服务状态、对话、PDF 上传、提交云解析。

**Terra 工作台**：证据优先模式、Mix / RAGAnything 切换、文献入库中状态、引用来源。

**接口**：`POST /api/rag/query`、`GET /api/raganything/status`、`POST /api/raganything/documents`、`POST /api/raganything/query`。

**状态**：服务异常 / 思考中 / 无引用 / 流式输出。

**设计注意**：对话 + 引用卡片；模式切换要轻量；引用要能点回论文。

---

### G. 三维地球

**用户任务**：从空间视角看数据，做演示/汇报素材。

**图层**：云层、地震、天气（气旋）、洋流、地质（断层/火山）。

**交互**：

- 时间轴回放（按年份过滤，带年份分布条）
- 悬停信息卡、点击聚焦
- 缩放、拖拽、重置
- 导出 PNG（带角标：深视地球 · GeoCamera / 经纬度 / 缩放 / 年份）
- 分享链接（lon/lat/zoom/layers/year）
- 巡游模式（大屏无人值守）
- 性能：动态分辨率、离屏暂停、`prefers-reduced-motion`、无 WebGL 回退海报

**页面**：`/earth` 全屏页（首页首屏也有一个入口）。

**设计注意**：全屏沉浸、控件克制；图层开关 + 时间轴 + 事件卡是三类核心控件。

## 3. 跨模块 / 系统能力

- **数据模型**：地震事件（时间、震级、深度、位置、震级类型、台网、定位源、误差、Gap/RMS）；论文（DOI、期刊、主题、证据类型、关系、分块）。
- **数据源**：区域台网 + 公开目录（USGS 等），入库到 PostGIS，SSE 推送。
- **事件为主线**：目录 → 事件 → 论文 → RAG → 结论，是同一条数据链。
- **无登录/权限体系**（当前）；实验室页面目前是中文，公司站有中英双语。
- **导出/分享**：三维地球导出 PNG、分享 URL；文献侧暂无导出。
- **必做的状态设计**：loading / empty / error / partial / offline（RAG 服务异常很常见）。
